# GestionClub

**A small Laravel app to manage the members of a club.**

A public member directory with biographies, accounts that must be approved by an administrator before they can see contact details or edit anything, and a simple admin screen to validate new sign-ups.

## Features

- **Public member directory** (`/membres`, plus a styled variant at `/membrescss`) and a page per member (`/membre/{id}`) showing name and biography.
- **Contact details protected**: a member's email is hidden from visitors, and from logged-in users who have not been validated yet.
- **Member profile**: a logged-in, validated user can create their own member profile and edit it, including a biography. You can only edit the profile whose address matches your account email.
- **Account validation workflow**: new accounts land on a "pending validation" page until an administrator approves them.
- **Admin screen** (`/admin/validations`): lists accounts waiting for approval and validates them in one click. Restricted to administrators.
- **Authentication** from Laravel Breeze: registration, login, password reset, email verification, password confirmation and profile management.

## Getting started

Requires PHP 8.3+, Composer, Node.js and npm.

```bash
git clone https://github.com/Nathan-Part/laravel.git
cd laravel/GestionClub
composer run setup
```

`composer run setup` installs the dependencies, creates `.env` from `.env.example`, generates the app key, runs the migrations and builds the assets. With the default SQLite configuration, create the database file first if it does not exist: `touch database/database.sqlite`.

Then start everything (web server, queue listener, logs and Vite) with:

```bash
composer run dev
```

Run the tests with `composer test`.

To approve accounts you need an administrator: set the `is_admin` column of a user to `1` in the database (for example with `php artisan tinker`). Administrators are never blocked by the validation step.

### Configuration

Copy `.env.example` to `.env`. The variables you will most likely touch:

| Variable | Purpose |
| --- | --- |
| `APP_NAME`, `APP_URL`, `APP_ENV`, `APP_DEBUG` | Application basics |
| `APP_KEY` | Generated by `php artisan key:generate` |
| `DB_CONNECTION` | Database driver (`sqlite` by default; MySQL variables `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` if you switch) |
| `MAIL_MAILER`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD` | Outgoing emails (verification, password reset) |

## Project structure

```
GestionClub/
├── app/
│   ├── Http/
│   │   ├── Controllers/     # Members, admin validation, profile, Breeze auth
│   │   ├── Middleware/      # EnsureUserIsValidated, EnsureUserIsAdmin
│   │   └── Requests/
│   └── Models/              # User, Membre, Biographie (one-to-one with Membre)

│   └── migrations/          # users, members, biographies, is_validated / is_admin flags
├── resources/
│   └── views/
│       ├── pages_site/      # Member list, member page, create/edit, admin validations
│       ├── auth/ profile/   # Breeze screens
│       └── layouts/ components/
├── routes/                  # web.php, auth.php
└── tests/                   # Feature and unit tests
```
